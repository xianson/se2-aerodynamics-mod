# Aerodynamics Mod: developer notes

Aerodynamic forces for SE2 grids: drag, lift, wings and compressibility from the grid's own shape, plus reentry
plasma. Scripts live in `Scripts/Simulation`. The offline tests are in `Tests/`.

## Testing

- **`tools/test_fast.sh`** (about 15 s, no game). Run it before every commit. It runs:
  - **ModCheck:** the game's exact script compile, plus rule MODVAR1. See `D:\aero\tools\ModCheck`.
  - **AeroBench gate:**
    - known shapes;
    - table vs exact forces on the small ships;
    - table cache round trip and edge cases;
    - wing repeatability;
    - rebuild garbage under 4 MB;
    - cache version vs sources.
  - **SurfaceTests:** 1,555 checks.
- **AeroBench modes** (`cd Tests/AeroBench; dotnet run -c Release -- <mode> <ships>`). Ships come from `Tests/data/*.boxes` (gitignored; exported in game with `aeroexport on`):
  - `damage` / `impact`: local updates after damage, against an exact rebuild;
  - `scale`: coarse vs fine cells;
  - `cache`: table cache timings;
  - `gcbuild`: garbage per build stage (`ALLOC=1` adds per-type dumps);
  - `tablehash`: see below.
- **In game:** the Orbital mod's harness (`Orbital Mod/tools/harness`) drives the game.
  - Red Ship crash test: `gridmove 1000000029 -112129 -17241 -170305`, then `gridvel 1000000029 500`. Concordia Research Facility 7 world.
  - Cost readout: `aerocost on` writes `[AERO-COST]` lines to the log.

## Force tables and their cache

- **Per frame, a lookup.** Each grid's forces come from a `ForceTable`: 486 flow directions, built in the background.
- **Damage updates.** A `ChunkedTable` (8 m chunks) updates the table locally after damage, without a full rebuild.
- **Disk cache** (`Drag/AeroTableCache.cs`, `%TEMP%\AeroMod\tables`).
  - Keyed by the grid's shape: block boxes in any order, block size, cell scale, face physics.
  - A reloaded world, a pasted blueprint or a copy loads its table in milliseconds instead of rebuilding.
  - Trimmed to 256 MB, least recently used first.
- **The version rule.** Any change to how tables, chunks or wings are built must bump `AeroTableCache.Version`. Otherwise players load stale tables.
  - The gate enforces this: it hashes the table-building sources into `Tests/table_sources.txt`.
  - After a bump, record the new hash with `dotnet run -- tablehash` in `Tests/AeroBench`.

## Reentry plasma

- **Files:** `Integration/AeroEntryFx.cs` (the logic) and `Integration/EntryFxBridge.cs` (the only reflection, because the particle API is outside the mod references).
- **The effect** (`Assets/Particles/AeroEntry_*`) is generated by `tools/particles/gen_entry.py` from the game's own definitions.
  - Compile it with `D:\aero\tools\build_mod_content.py "<this mod>"`.
  - The game allows at most 4 keyframes over a particle's life. More, and the world fails to load (the generator asserts this).
- **Server side:** each grid publishes its nose, frontal radius and heat, where heat = √(ρ/1.225)·(V/1 km/s)³ with a 2 s lag.
- **Client side:** the effect's strength is its timeline's time, held between 0 and 1 s of a 2 s effect.
- **Other mods:** `AeroEntryFx.External` lets another mod supply a grid's air velocity and glow. The Orbital mod's on-rails braking band does this.
- **Knobs** (set with `aeroset AeroEntryFx.<name> <value>` from the Orbital harness):

  | Knob | Default | What it does |
  |---|---|---|
  | `OnsetHeat` | 0.3 | Heat at which the plasma starts |
  | `FullHeat` | 5 | Heat at full strength |
  | `MaxActive` | 16 | Most effects at once, nearest the camera |
  | `TestSpeed` | off | A parked grid glows as if flying forward at this speed |
- **Single player only for now:** the published state is shared memory.

## Performance notes

- **Garbage:** rebuilds and damage updates reuse pooled tables. A Red Ship rebuild produces about 20 MB of garbage; no table allocation recurs.
- **Lookups:** plasma and flames find their published grid in O(1), by remembering last frame's match.
- **Frame budget:** `AeroFrameBudget` caps aero at 1 ms per frame; piloted and fast grids are exempt.
- **Background work:** `AeroWork` runs it in priority order on 2 workers.

## Content build

`D:\aero\tools\build_mod_content.py` compiles `Assets` into `Content`. Each build keeps the previous Content as `Content.before-<stamp>`; those folders are gitignored.
